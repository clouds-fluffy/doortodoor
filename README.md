# 문앞까지

건물 정문이 아니라, 오늘 함께 탄 사람에게 맞는 주차장과 출입구 '문 앞까지' 안내하는 차량용 도착 안내 앱입니다.

현대자동차그룹 차량용 앱 개발 공모전 1차 접수용 저장소입니다. Pleos Connect 에뮬레이터에서 동작하는 **안드로이드 앱(추천 로직과 화면, SDK 연동 전)**과, 전체 흐름을 브라우저에서 볼 수 있는 **웹 프로토타입**이 들어 있습니다.

## 1. 앱 이름 및 한 줄 소개

- 앱 이름: 문앞까지
- 한 줄 소개: 대형병원처럼 주차장과 출입구가 여러 개인 곳에서, 목적지와 오늘의 조건(가장 가까운 입구 / 엘리베이터 가까이 / 휠체어·유모차 / 빨리 태우고 나가기)을 고르면 그에 맞는 주차장과 출입구를 추천하고 기본 내비게이션에 목적지로 넘깁니다.

## 2. 실행 방법

### 안드로이드 앱

1. Android Studio에서 이 저장소를 엽니다.
2. Pleos Connect Emulator를 실행합니다.
3. `app` 구성을 Run 하거나, `apk/다온_문앞까지_release.apk`를 에뮬레이터에 설치합니다. (`adb install apk/다온_문앞까지_release.apk`)
4. 목적지(암센터 / 정형외과 / 응급센터) → 조건 → `안내 시작` 순서로 누릅니다.
5. 이후 화면의 `현재 거리 499m (테스트)` → `도착 (테스트)` → `문 열림 (테스트)` 버튼으로 주행·도착·하차 순간을 차례로 확인합니다.

같은 암센터를 고른 뒤 조건만 '엘리베이터 가까이'와 '빨리 태우고 나가기'로 바꿔 보면 추천 지점이 지하주차장과 정문 승하차 구역으로 달라집니다.

### 웹 프로토타입

`prototype/index.html`을 크롬 등 최신 브라우저로 엽니다. 설치나 빌드 과정은 없습니다. 차량 화면 전체(주행 정보 + 내비게이션 + 문앞까지)를 한 화면에 그려, 앱이 내비게이션 옆 창에서 어떻게 보이는지 확인할 수 있습니다.

## 3. 테스트 환경 및 필요한 설정

- 앱: Kotlin, Android View. 외부 라이브러리는 AndroidX AppCompat만 사용합니다. 별도 계정이나 권한 설정은 필요하지 않습니다.
- 앱의 `야간 모드` 버튼으로 주간·야간 화면을 바꿀 수 있고, '자주 가는 곳'은 기기에 저장됩니다.
- 웹 프로토타입: Chrome(데스크톱), 화면 폭 1280px에서 확인했습니다. 인터넷 연결은 글꼴(Asta Sans)을 불러올 때만 사용합니다.

## 4. Pleos Connect 에뮬레이터 버전과 화면 규격

- 에뮬레이터: Pleos Connect v2.1.0 (Android 14, 시스템 이미지 API Level 34)
- 화면 규격: Pleos Connect UI Design Guide의 Connect-S 17인치(2560 × 1440dp) 기준입니다.
  - 넓은 창: 왼쪽에 시설 약도 카드, 오른쪽에 너비 840의 안내 칸. 바깥 여백 40, 칸 사이 20, 모서리 40
  - 세로 창(840 × 1184dp): 위에 약도, 아래에 안내 내용
  - 큰 버튼 높이 100·모서리 32, 중간 버튼 높이 80·모서리 24, 주간·야간 색상은 가이드의 Colors 값
- 글꼴은 기기 기본 글꼴을 씁니다. 가이드의 Asta Sans는 아직 넣지 않았습니다.

## 5. APK 파일 위치

- `apk/다온_문앞까지_release.apk` (서명한 release 빌드)

## 지금 되는 것과 아직 안 된 것

| 구분 | 내용 |
|---|---|
| 되는 것 | 시설 데이터에서 조건별 주차장·출입구 추천 계산, 추천 결과·주행 중·시설 근처·도착·걸어갈 길 화면, 3D 시설 약도, 자주 가는 곳 저장, 주간·야간 화면 |
| 아직 안 된 것 | **Pleos Connect SDK 연동.** 거리 변화, 도착, 문 열림은 지금 화면의 테스트 버튼으로 대신합니다. 기본 내비게이션에 목적지를 넘기는 호출도 아직 넣지 않았습니다. |

SDK를 연결할 자리는 `MainActivity.kt`의 "SDK 연동 지점" 함수 네 곳에 표시해 두었습니다.

| 순간 | 연결할 SDK / API | 코드 위치 |
|---|---|---|
| 안내 시작 | NaviHelper `requestRoute()`, FusedLocation `addProximityAlert()` | `startGuidance()` |
| 시설 근처 진입 | FusedLocation `onTransition(ENTER)` | `onDistanceToHospitalChanged()` |
| 도착 | NaviHelper `onDestinationArrived()` | `onDestinationArrived()` |
| 하차·탑승 | Vehicle Door `registerDoorPosition()` | `onDoorOpened()` |

## 설계 원칙

- 경로 안내는 하지 않습니다. 길 안내와 음성 안내는 기본 내비게이션이 맡고, 문앞까지는 어디로 갈지 정해 목적지로 넘기고 도착 지점 정보를 보여줍니다.
- 주행 중 화면에는 약도에 차량 경로 선을 그리지 않고 도착 지점만 표시합니다.
- 목적지 설정은 사용자가 `안내 시작`을 눌렀을 때만 합니다.

## 추천 엔진

- 시설 데이터: 건물, 출입구, 주차장, 지점(Node), 연결(Edge), 방문지
- 노드·엣지 그래프에서 다익스트라 알고리즘으로 차량 경로와 보행 경로를 따로 계산하고, 조건에 따라 가중치와 후보 지점을 바꿉니다.
  - 엘리베이터 가까이: 계단이 있는 보행 구간에 큰 추가 비용
  - 휠체어·유모차: 계단 구간 제외
  - 빨리 태우고 나가기: 주차장 대신 승하차 구역만 후보
  - 가장 가까운 입구: 걷는 거리가 가장 짧은 지점
- 앱(Kotlin)과 웹 프로토타입(JavaScript)은 같은 데이터와 계산을 쓰며, 목적지 3곳 × 조건 4가지의 12가지 조합에서 같은 결과가 나옵니다.

## 데이터에 관하여

'한빛대학교병원'은 **가상의 병원**입니다. 실제 병원이 아니며, 건물 배치와 거리, 소요 시간 값은 모두 검증을 위해 임의로 정한 값입니다.
